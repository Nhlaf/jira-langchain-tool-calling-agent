# Jira LangChain Agent

A small command-line assistant that uses an LLM to choose among five Jira tools. The model sees business operations and their input schemas; the Jira client owns all REST API paths, authentication, and payloads.

## Architecture

```text
User request
     |
     v
ChatGroq (tool-selection judge)
     | chooses a named tool and business-level arguments
     v
LangChain tool layer
     | calls a JiraClient method
     v
JiraClient (credentials, HTTP, endpoint paths, payloads, errors)
     |
     v
Jira Cloud REST API
     |
     v
Tool result -> LLM -> natural-language response
```

The LLM is responsible for interpreting intent and selecting a tool through LangChain's `bind_tools` interface. The agent executes the tool call requested by the model and returns its result to the model for a final explanation. There is no keyword-based router. The model does not construct Jira HTTP requests, endpoint paths, authentication headers, or Jira JSON payloads; those stay in `tools/jira_client.py`.

## Tools

- `get_issue_details(issue_key)`: retrieve details for an existing issue such as its summary, description, status, type, assignee, reporter, priority, and project.
- `search_issues(jql, max_results=50)`: search Jira with JQL and return up to 100 compact issue results.
- `create_story(project_key, summary, description)`: create a Jira Story.
- `create_bug(project_key, summary, description)`: create a Jira Bug.
- `create_task(project_key, summary, description)`: create a Jira Task.

Each create tool sets its Jira issue type internally. Descriptions are converted to Jira Cloud's Atlassian Document Format by the client.

## Requirements and Setup

Python 3.11 or newer is required. The dependencies use LangChain's `ChatGroq.bind_tools` and `langchain_core.tools.tool` interfaces.

```powershell
cd jira-langchain-agent
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Fill in `.env` (or copy the placeholders from `.env.example`):

```env
JIRA_BASE_URL=https://your-domain.atlassian.net
JIRA_EMAIL=your-email@example.com
JIRA_API_TOKEN=your-api-token
GROQ_API_KEY=your-groq-api-key
GROQ_MODEL=llama-3.3-70b-versatile
```

Create `GROQ_API_KEY` in the Groq console. `GROQ_MODEL` is optional and defaults to `llama-3.3-70b-versatile`; select a model available to your Groq account that supports tool calling. The `.env` file is excluded from Git; never commit real credentials.

## Run

From the project directory:

```powershell
python main.py
```

Example requests:

```text
Tell me the details of SCRUM-123.
Search Jira for open tasks in SCRUM using JQL: project = SCRUM AND issuetype = Task AND statusCategory != Done
Create a story in SCRUM called "Payment history" with description "Show previous payments to customers."
Create a task in SCRUM called "Update payment validation" with description "Validate payment fields before submission."
Create a bug in SCRUM called "Payment button fails" with description "Submitting the payment form does not work."
```

For each model-selected operation, the CLI prints the selected tool name before the Jira operation runs. For example:

```text
User: Search Jira for open tasks in SCRUM using JQL: project = SCRUM AND issuetype = Task AND statusCategory != Done
Selected tool: search_issues
Executing Jira operation...
Assistant: Found 3 matching issues: SCRUM-12, SCRUM-9, SCRUM-3.
```

The assistant asks a follow-up when required information is missing rather than guessing. Tool arguments are generated by the model from the conversation; Jira confirms actual results.

Tests mock HTTP and model responses; they do not require Jira credentials or an LLM API key.


## Errors and Security

The CLI checks for `JIRA_BASE_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN`, and `GROQ_API_KEY` before starting and names missing settings. The Jira client translates authentication, permission, not-found, validation, network, and malformed-response failures into useful messages. Jira credentials are read only by the client layer; the model receives tool schemas and tool results, never secrets or HTTP implementation details.

The design intentionally separates intent from integration: LangChain gives the model callable business tools, while `JiraClient` alone knows how to communicate with Jira. Adding or changing an endpoint therefore does not require teaching the model Jira's REST API.
